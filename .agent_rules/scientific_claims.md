# Scientific admission and evidence

Use this guide for analysis, comparisons and scientific release claims.
[Backend contracts](../docs/development/backend_scientific_contracts.md) and
[v4 migration](../docs/development/run_ownership_migration.md) own exact semantics.

## Evidence planes

| Evidence | Establishes |
| --- | --- |
| Parse/shape validation | Checked notation/representation constraints |
| Scientific admission | Selected backend's input/composition contract |
| Source/parameter binding | Recorded bytes, values and transformations |
| Native runtime receipt | Named released runtime produced validated current results |
| Numerical witness | Recorded observations for specified inputs and precision |
| Formal proof | Named theorem checked under recorded definitions, assumptions and toolchain |

Source-pair success is custody evidence. It cannot prove a theorem, universal
equivalence, extraction correctness, convergence or hardware performance.
LLM explanations and generated-script success are not proofs.

## Inputs and transformations

Reject invalid probability mass, dimensions, values and ambiguous orientation
under the strict contract. Preserve factor/agent parameters. Validate Gaussian
covariances and complete goal/control pairs. Allowed rounding/demo transforms
need explicit provenance. Do not invent missing priors, confidence, free energy
or policy optimization to produce plausible output.

## Comparisons

Join compatible model IDs, source hashes, inference meaning, inputs and precision.
Names/shapes cannot admit comparisons. Filtering, full-sequence smoothing and
different action conditioning retain their semantics.

Categorical diagnostics describe validated probability/sample traces; Gaussian
uncertainty comes from covariance. Keep factor/agent identity and bounded joint
composition. Missing/incompatible evidence produces unavailable/refused output
with reasons across JSON, Markdown and plots.

## Report and verify

Record exact source/runtime/toolchain, fixture, selection, precision, seed/sample
settings, native schema and observations. Qualify stochastic agreement, entropy
and runtime as measured witnesses. Preserve unsuccessful cases. Test incompatible
bindings, missing quantities, covariance and refusal outputs. Native claims need
released-runtime public execution; formal claims need independent proof evidence.
